## 0. 先明确：这条链路涉及哪些文件

一次实盘下单，数据对象会流经 4 个核心文件（本仓库都有）：

| 文件 | 角色 | 本文关注的类/方法 |
|---|---|---|
| `vnpy/trader/object.py` | 数据对象定义 | `OrderRequest` / `OrderData` / `TradeData` / `PositionData` |
| `vnpy/trader/engine.py` | 主引擎 + 订单管理系统 | `MainEngine.send_order` / `OmsEngine.process_*_event` |
| `vnpy/trader/gateway.py` | 券商接口抽象（生产者） | `BaseGateway.send_order` / `on_order` / `on_trade` / `on_position` |
| `vnpy/trader/converter.py` | 开平仓/持仓换算 | `OffsetConverter` / `PositionHolding` |

> 说明：具体某家券商的 Gateway（如 `vnpy_xtp`）是**独立 pip 包**，不在本仓库。但它必须实现 `BaseGateway` 的抽象方法，所以本文引用 `BaseGateway` 里的**契约（docstring + 回报方法）**即可完整还原链路——这正是抽象基类的价值。

## 1. 股票交易的一个关键前提：`net_position`（净持仓）

在讲流程前，必须先建立一个对**股票**至关重要的认知：股票是**净持仓（net position）**品种。

- 股票只有「持有多少股」这一个数，**没有多头腿/空头腿之分**，也**没有平今/平昨**（那是期货的概念）。
- 因此券商推送的股票 `ContractData` 通常设置 `net_position=True`。
- 这个标志直接决定了 `OffsetConverter` **是否介入**。看 `is_convert_required`：

```390:402:vnpy/trader/converter.py
    def is_convert_required(self, vt_symbol: str) -> bool:
        """
        Check if the contract needs offset convert.
        """
        contract: ContractData | None = self.get_contract(vt_symbol)

        # Only contracts with long-short position mode requires convert
        if not contract:
            return False
        elif contract.net_position:
            return False
        else:
            return True
```

**结论**：对 `net_position=True` 的股票，`is_convert_required` 返回 `False`，`OffsetConverter` 全程**跳过换算**。所以股票的下单请求不会被拆成平今/平昨，持仓也不走 `PositionHolding` 的多空腿逻辑，而是**直接由券商推送的 `PositionData` 覆盖更新**。

> 对比：期货（如 SHFE 螺纹钢）`net_position=False`，`OffsetConverter` 才会介入，把「平仓」拆成平今/平昨——那是本文末尾「延伸」里对照的内容。

## 2. 数据对象定义（链路上流动的 4 个主角）

### 2.1 `OrderRequest`——你的下单意向

买入 600000 时，先构造一个 `OrderRequest`：

```320:355:vnpy/trader/object.py
@dataclass

    """
    Request sending to specific gateway for creating a new order.
    """

    symbol: str
    exchange: Exchange
    direction: Direction
    type: OrderType
    volume: float
    price: float = 0
    offset: Offset = Offset.NONE
    reference: str = ""

    def __post_init__(self) -> None:
        """"""
        self.vt_symbol: str = f"{self.symbol}.{self.exchange.value}"

    def create_order_data(self, orderid: str, gateway_name: str) -> OrderData:
        """
        Create order data from request.
        """
        order: OrderData = OrderData(
            symbol=self.symbol,
            exchange=self.exchange,
            orderid=orderid,
            type=self.type,
            direction=self.direction,
            offset=self.offset,
            price=self.price,
            volume=self.volume,
            reference=self.reference,
            gateway_name=gateway_name,
        )
        return order
```

**股票买入的字段填法**：

```python
from vnpy.trader.object import OrderRequest
from vnpy.trader.constant import Exchange, Direction, Offset, OrderType

buy_req = OrderRequest(
    symbol="600000",
    exchange=Exchange.SSE,
    direction=Direction.LONG,    # 买入 = 做多方向
    type=OrderType.LIMIT,        # 限价单
    volume=100,                  # A 股 1 手 = 100 股
    price=10.0,
    offset=Offset.NONE,          # 股票无开平概念，填 NONE
)
# buy_req.vt_symbol == "600000.SSE"（__post_init__ 自动拼接）
```

- **要点 1**：股票 `offset` 填 `Offset.NONE`（无开平概念）。
- **要点 2**：`OrderRequest` 本身**还不是委托**，它只是「请求」。`create_order_data()` 才把它转成带 `orderid` 的正式委托对象 `OrderData`（这一步在 Gateway 内部发生，见第 4 步）。

### 2.2 `OrderData`——委托状态跟踪器

## 3. 一次买入的完整流转（逐步 + 代码引用）

### 步骤总览

```
策略/脚本                MainEngine          Gateway(券商)         EventEngine        OmsEngine
   │  buy_req                                                                            
   │─── send_order ──────►│                                                             
   │                      │── gateway.send_order ─►│                                    
   │                      │                        │ create_order_data → OrderData(SUBMITTING)
   │                      │                        │── on_order ──────►│                
   │                      │◄── return vt_orderid ──│                   │── EVENT_ORDER ─►│ 存入 orders/active_orders
   │◄─── vt_orderid ──────│                                                             
   │                                               │（交易所撮合成交）                    
   │                                               │── on_trade ──────►│── EVENT_TRADE ─►│ 存入 trades
   │                                               │── on_order ──────►│── EVENT_ORDER ─►│ 更新为 ALLTRADED（移出 active）
   │                                               │── on_position ───►│── EVENT_POSITION►│ 更新 positions
```

### 步骤 1：策略调用 `MainEngine.send_order`

```254:264:vnpy/trader/engine.py
    def send_order(self, req: OrderRequest, gateway_name: str) -> str:
        """
        Send new order request to a specific gateway.
        """
        gateway: BaseGateway | None = self.get_gateway(gateway_name)
        if gateway:
            self.write_log(_("委托下单 -> {}：{}").format(gateway_name, req))

            return gateway.send_order(req)
        else:
            return ""
```

`MainEngine` 只做一件事：根据 `gateway_name` 找到对应 Gateway，把请求**转发**给它，并返回 `vt_orderid`。主引擎不关心券商细节——这正是解耦。

### 步骤 2：`Gateway.send_order` 把请求变成委托并发往交易所

`BaseGateway.send_order` 是抽象方法，其 docstring 精确规定了每个券商子类必须做什么：

```196:212:vnpy/trader/gateway.py
    @abstractmethod
    def send_order(self, req: OrderRequest) -> str:
        """
        Send a new order to server.

        implementation should finish the tasks blow:
        * create an OrderData from req using OrderRequest.create_order_data
        * assign a unique(gateway instance scope) id to OrderData.orderid
        * send request to server
            * if request is sent, OrderData.status should be set to Status.SUBMITTING
            * if request is failed to sent, OrderData.status should be set to Status.REJECTED
        * response on_order:
        * return vt_orderid

        :return str vt_orderid for created OrderData
        """
        pass
```

所以任意券商的 `send_order` 内部都会：
1. 用 `req.create_order_data(orderid, gateway_name)` 生成 `OrderData`（见 §2.1 代码，`object.py:339-355`）；
2. 分配唯一 `orderid`；
3. 发往交易所，设 `status = SUBMITTING`（失败则 `REJECTED`）；
4. 调用 `on_order(order)` 把这张委托推回系统；
5. 返回 `vt_orderid`。

### 步骤 3：`on_order` 推送「委托事件」（一次推两个）

```109:115:vnpy/trader/gateway.py
    def on_order(self, order: OrderData) -> None:
        """
        Order event push.
        Order event of a specific vt_orderid is also pushed.
        """
        self.on_event(EVENT_ORDER, order)
        self.on_event(EVENT_ORDER + order.vt_orderid, order)
```

注意这里**推两个事件**：
- `EVENT_ORDER`（通用）→ 给 OMS、界面等全局监听者；
- `EVENT_ORDER + vt_orderid`（精准）→ 让某个策略只收自己那张委托的回报。

`on_event` 只是把事件塞进队列（**异步**，不阻塞）：

```86:91:vnpy/trader/gateway.py
    def on_event(self, type: str, data: object = None) -> None:
        """
        General event push.
        """
        event: Event = Event(type, data)
        self.event_engine.put(event)
```

### 步骤 4：`OmsEngine.process_order_event` 缓存委托

事件引擎后台线程把 `EVENT_ORDER` 分发给 OMS 的处理函数（OMS 在 `__init__` 里注册了它，见 `engine.py:387`）：

```399:414:vnpy/trader/engine.py
    def process_order_event(self, event: Event) -> None:
        """"""
        order: OrderData = event.data
        self.orders[order.vt_orderid] = order

        # If order is active, then update data in dict.
        if order.is_active():
            self.active_orders[order.vt_orderid] = order
        # Otherwise, pop inactive order from in dict
        elif order.vt_orderid in self.active_orders:
            self.active_orders.pop(order.vt_orderid)

        # Update to offset converter
        converter: OffsetConverter | None = self.offset_converters.get(order.gateway_name, None)
        if converter:
            converter.update_order(order)
```

- 委托存入 `self.orders`（全部委托）字典；
- 用 `is_active()` 维护 `self.active_orders`（还挂在市场上的委托）：`SUBMITTING/NOTTRADED/PARTTRADED` 时加入，成交/撤销/拒单后移除。这就是 `is_active()` 的实战用途；
- 最后交给 `OffsetConverter`——但**对股票**，下一步 `is_convert_required` 会因 `net_position=True` 直接返回、不做任何事（见 §1）。

> 补充：`OffsetConverter` 是**每个 gateway 首次收到 `contract` 事件时自动创建**的，见 `process_contract_event`（`engine.py:441-448`）。

### 步骤 5：交易所撮合 → `on_trade` 推送「成交事件」

买单被撮合成交后，券商回调 `on_trade`（同样一次推两个事件）：

```101:107:vnpy/trader/gateway.py

        """
        Trade event push.
        Trade event of a specific vt_symbol is also pushed.
        """
        self.on_event(EVENT_TRADE, trade)
        self.on_event(EVENT_TRADE + trade.vt_symbol, trade)
```

OMS 处理成交事件：

```416:424:vnpy/trader/engine.py
    def process_trade_event(self, event: Event) -> None:
        """"""
        trade: TradeData = event.data
        self.trades[trade.vt_tradeid] = trade

        # Update to offset converter
        converter: OffsetConverter | None = self.offset_converters.get(trade.gateway_name, None)
        if converter:
            converter.update_trade(trade)
```

- 成交存入 `self.trades`；
- 交给 converter——对股票同样跳过（`net_position=True`）。
- **同时**，成交发生后交易所也会再推一个 `on_order`（status 变为 `PARTTRADED` 或 `ALLTRADED`），再次走步骤 4：当变为 `ALLTRADED` 时 `is_active()` 为 `False`，该委托被移出 `active_orders`。

> 若买 100 股一次全成 → 一笔 `TradeData` + 一个 `ALLTRADED` 的 `OrderData`。
> 若被拆成 60 + 40 两笔成交 → 两笔 `TradeData`，中间一个 `PARTTRADED`、最后一个 `ALLTRADED` 的 `OrderData`。这就是「一委托多成交」。

### 步骤 6：持仓更新 → `on_position`

股票买入成交后，券商推送最新持仓：


- 最新持仓**覆盖式**存入 `self.positions[vt_positionid]`。买入 100 股后，`600000.SSE` 的 `PositionData.volume` 变为 100，`direction=LONG`，`price` 为买入均价。
- converter 对股票依旧跳过。所以**股票持仓完全以券商推送的 `PositionData` 为准**（券商是权威数据源）。

至此，一次买入完成：`OrderRequest → OrderData(SUBMITTING→...→ALLTRADED) → TradeData → PositionData(volume=100)`。策略之后可通过 `MainEngine.get_position(vt_positionid)`（转发到 `OmsEngine.get_position`，见 `engine.py:148`、`480-484`）查询到这个持仓。

## 4. 一次卖出的完整流转

卖出和买入**走的是同一套链路**（步骤 1~6 完全一致），差别只在 `OrderRequest` 的字段和最终持仓变化方向。

### 4.1 卖出请求的字段填法

```python
sell_req = OrderRequest(
    symbol="600000",
    exchange=Exchange.SSE,
    direction=Direction.SHORT,   # 卖出 = SHORT 方向
    type=OrderType.LIMIT,
    volume=100,
    price=10.5,
    offset=Offset.NONE,          # 股票依旧无开平概念
)
```

- **关键**：股票「卖出」用 `Direction.SHORT`。这不代表"做空"——因为 A 股不能裸卖空，这里的 SHORT 只是「卖出方向」，前提是你**已经持有这 100 股**。
- 若手里没有持仓就发卖单，券商/交易所会**拒单（REJECTED）**，链路在步骤 2 的失败分支就终止（`status=REJECTED`，走 `on_order` → OMS 记录但不进 `active_orders`）。

### 4.2 卖出成交后的持仓变化

- 步骤 1~5 与买入完全相同（同样经过 `send_order → on_order → on_trade`）。
- 步骤 6：券商推送更新后的 `PositionData`，`600000.SSE` 的 `volume` 从 100 减为 0（或部分卖出后的剩余量）。

### 4.3 T+1 的体现

A 股 T+1：**当天买入的股票当天不能卖**。这个约束在真实券商侧校验，代码层面的体现是 `PositionData.yd_volume`（昨仓量）——只有 `yd_volume` 部分是当天可卖的。若你尝试卖出超过 `yd_volume` 的量，券商会拒单。（回测引擎则通过数据规则模拟这一限制。）

## 5. 为什么股票这条链路「看不到 OffsetConverter 干活」——对照期货

这是理解股票 vs 期货差异的关键。同样是「卖出平仓」，走到 `OffsetConverter.convert_order_request` 时：

```367:388:vnpy/trader/converter.py
    def convert_order_request(
        self,
        req: OrderRequest,
        lock: bool,
        net: bool = False
    ) -> list[OrderRequest]:
        """"""
        if not self.is_convert_required(req.vt_symbol):
            return [req]

        holding: PositionHolding | None = self.get_position_holding(req.vt_symbol)

        if not holding:
            return [req]
        elif lock:
            return holding.convert_order_request_lock(req)
        elif net:
            return holding.convert_order_request_net(req)
        elif req.exchange in {Exchange.SHFE, Exchange.INE}:
            return holding.convert_order_request_shfe(req)
        else:
            return [req]
```

- **股票**（`net_position=True`）：第一行 `is_convert_required` 为 `False` → 直接 `return [req]`，**原样返回，不拆单**。
- **期货**（`net_position=False`，且在上期所/能源所）：走 `convert_order_request_shfe`，把「平仓」拆成 `CLOSETODAY`（平今）/ `CLOSEYESTERDAY`（平昨），因为上期所要求显式区分今昨仓（手续费不同）。

同理，持仓更新时期货才会走 `PositionHolding.update_trade` 里那套复杂的多空腿/今昨仓逻辑（`converter.py:71-107`），股票则完全不碰，直接用券商推的 `PositionData`。

> **一句话**：`net_position` 这一个布尔标志，就是「股票简单、期货复杂」在代码里的分水岭。

## 7. 小结与自测

**这条链路的 5 个记忆锚点**：

1. `OrderRequest` 是「请求」，`create_order_data()` 之后才是「委托 `OrderData`」——转换发生在 Gateway 内部。
2. `MainEngine` 只做转发；真正干活的是 `Gateway`（发单/回报）和 `OmsEngine`（缓存状态）。
3. 每个回报（`on_order/on_trade/on_position`）都**推两个事件**：通用 + 带后缀精准。
4. `is_active()` 驱动 `active_orders` 的增删——委托生命周期管理的核心。
5. 股票 `net_position=True` → `OffsetConverter` 全程跳过 → 持仓以券商推送的 `PositionData` 为准。
