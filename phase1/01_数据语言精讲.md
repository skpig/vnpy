## 一、为什么「数据语言」是地基

统领性认知：**vnpy 的所有代码，本质是在"生产、传递、消费"一组标准数据对象。**

- **Gateway** 生产它们（把券商数据翻译成 `TickData`/`OrderData`…）；
- **EventEngine** 传递它们（`Event.data` 装的就是这些对象）；
- **OmsEngine** 缓存它们（一堆 `dict[str, XxxData]`）；
- **策略** 消费它们（`on_bar(bar: BarData)`、`on_trade(trade: TradeData)`）。

所以这些对象是全框架的**通用货币**。认全这套"名词"，读代码就从"猜"变成"读"。

| 文件 | 内容 | 类比 |
|---|---|---|
| `constant.py` | **枚举**：给「方向/状态/交易所」定下有限固定的合法取值 | 语言的"词性/固定搭配" |
| `object.py` | **数据对象**：把一组字段打包成带语义的结构体 | 语言的"名词" |

## 二、object.py 的总体架构：两大家族

```
object.py
├── 数据对象家族（描述"已经发生/存在的事实"，多继承 BaseData）
│   ├── BaseData          ← 所有数据对象的根
│   ├── 行情类：TickData, BarData
│   ├── 交易类：OrderData, TradeData, QuoteData
│   ├── 账户持仓类：PositionData, AccountData
│   ├── 合约类：ContractData
│   └── 日志类：LogData
│
└── 请求对象家族（描述"我想让 Gateway 去做的动作"，不继承 BaseData）
    ├── SubscribeRequest   订阅行情
    ├── OrderRequest       下单
    ├── CancelRequest      撤单
    ├── HistoryRequest     查历史
    └── QuoteRequest       做市报价
```

**「数据 vs 请求」二分法**（关键）：

| | 数据对象 | 请求对象 |
|---|---|---|
| 描述 | **事实**（市场发生了什么、我持有什么） | **意图**（我想订阅/下单/撤单） |
| 数据流方向 | Gateway → 你（回报/推送） | 你 → Gateway（指令） |
| 是否带 `gateway_name` | **带**（继承 BaseData） | **不带**（发给谁在调用时指定） |

记忆锚点：**数据对象带 `gateway_name`，请求对象不带。**

## 三、BaseData：根对象 + 复合 ID 机制

这是阶段 1 **最该吃透的机制**。

```17:27:vnpy/trader/object.py
@dataclass
class BaseData:
    """
    Any data object needs a gateway_name as source
    and should inherit base data.
    """

    gateway_name: str

    extra: dict | None = field(default=None, init=False)
```

### 3.1 两个公共字段

- **`gateway_name`**：这条数据来自哪个接口。多券商并联时必须知道来源，否则无法回发指令、无法区分同名委托。
- **`extra`（`init=False`）**：预留扩展字典，不出现在构造函数参数里，默认 `None`。给特定 Gateway 塞非标准字段用的"逃生舱口"。

### 3.2 核心机制：`__post_init__` 自动拼「复合 ID」

`@dataclass` 生成的 `__init__` 跑完后立刻调用 `__post_init__`，vnpy 在这里拼出**全局唯一 ID**。这是整个框架"能在字典里索引到任何东西"的基础。

| 复合 ID | 拼接规则 | 出现在 |
|---|---|---|
| `vt_symbol` | `f"{symbol}.{exchange.value}"` | 几乎所有对象 |
| `vt_orderid` | `f"{gateway_name}.{orderid}"` | OrderData, TradeData |
| `vt_tradeid` | `f"{gateway_name}.{tradeid}"` | TradeData |
| `vt_positionid` | `f"{gateway_name}.{vt_symbol}.{direction.value}"` | PositionData |
| `vt_accountid` | `f"{gateway_name}.{accountid}"` | AccountData |

### 3.3 为什么要带前缀？——「命名空间」防撞号（重点）

复合 ID 要在 OMS 的全局字典里当唯一 key，前缀就是防止"撞号"的手段。**前缀 = 命名空间**（就像"腾讯.001"和"阿里.001"是不同的人）。分两类：

**类 A：`vt_symbol` 加交易所后缀 —— 防不同交易所代码撞号**
- `000001` 在深交所是"平安银行"，在上交所是"上证指数"。
- 加后缀区分：`000001.SZSE`（平安银行）vs `000001.SSE`（上证指数）。

**类 B：`vt_orderid` 等加 gateway_name 前缀 —— 防不同券商编号撞号**
- `orderid` 由券商各自分配。同时连 CTP 和 IB 时，两家都可能给出 `orderid="123"`。
- 加前缀：`CTP.123` vs `IB.123`，存进 OMS 字典时互不覆盖。

| 字段 | 前缀 | 防的是什么撞号 |
|---|---|---|
| `vt_symbol` | 交易所 | 不同交易所的相同代码 |
| `vt_orderid` / `vt_tradeid` / `vt_accountid` | gateway_name | 不同券商的相同编号 |
| `vt_positionid` | gateway_name + **direction** | 同一合约的多头腿 vs 空头腿（见 §4.5） |

## 四、数据对象逐个精读

### 4.1 TickData（切片行情）

```29:84:vnpy/trader/object.py
@dataclass
class TickData(BaseData):
    """
    Tick data contains information about:
        * last trade in market
        * orderbook snapshot
        * intraday market statistics.
    """

    symbol: str
    exchange: Exchange
    datetime: Datetime

    name: str = ""
    volume: float = 0
    turnover: float = 0
    open_interest: float = 0
    last_price: float = 0
    last_volume: float = 0
    limit_up: float = 0
    limit_down: float = 0

    open_price: float = 0
    high_price: float = 0
    low_price: float = 0
    pre_close: float = 0

    bid_price_1: float = 0
    ...
    ask_volume_5: float = 0

    localtime: Datetime | None = None
```

按 docstring 的三重身份记字段：

1. **最新成交**：`last_price`、`last_volume`。
2. **订单簿快照**：`bid_price_1..5`/`ask_price_1..5` + 量（5 档盘口）。
3. **日内统计**：`volume`（累计成交量）、`turnover`（累计成交额）、`open_interest`（持仓量，期货专用）、`open/high/low_price`、`pre_close`（昨收）、`limit_up/limit_down`（涨跌停价）。

易忽略细节：
- **`volume`（累计，单调递增）vs `last_volume`（最新一笔）**：算成交量增量要用 `本tick.volume − 上tick.volume`。
- **`turnover`（成交额，钱）vs `volume`（成交量，手/股）**：相除可估均价。
- **`open_interest`（持仓量）**：期货独有，反映资金沉淀；股票没有。
- **`datetime`（交易所时间）vs `localtime`（本地收到时间）**：两者之差衡量行情延迟。

### 4.4 TradeData（成交，不可撤）


### 4.5 PositionData（持仓）

```178:197:vnpy/trader/object.py
@dataclass
class PositionData(BaseData):
    """
    Position data is used for tracking each individual position holding.
    """

    symbol: str
    exchange: Exchange
    direction: Direction

    volume: float = 0
    frozen: float = 0
    price: float = 0
    pnl: float = 0
    yd_volume: float = 0

    def __post_init__(self) -> None:
        """"""
        self.vt_symbol: str = f"{self.symbol}.{self.exchange.value}"
        self.vt_positionid: str = f"{self.gateway_name}.{self.vt_symbol}.{self.direction.value}"
```

- **`direction` 必填且拼进 `vt_positionid`**——关键设计：期货**同一合约可同时持有多空两笔独立持仓**（如 rb2405 同时有多单 5 手、空单 3 手）。若 ID 不带 direction，两笔会在字典里互相覆盖。加 `direction` 后缀区分：
  - 多头 → `GW.rb2405.SHFE.多`
  - 空头 → `GW.rb2405.SHFE.空`
  - 这又是"防撞号 / 命名空间"的应用，只不过区分的是同一合约的多空腿。
  - 股票不能持负股，只用 `.多`。
- **`volume`（总持仓）vs `frozen`（冻结，已挂平仓单占用）**：可动用 = `volume − frozen`。
- **`yd_volume`（昨仓）**：T+1 / 平昨关键；`volume − yd_volume` = 今仓。
- **`price`（持仓均价）**、**`pnl`（浮动盈亏）**。

### 4.6 AccountData（账户）

```200:215:vnpy/trader/object.py
@dataclass
class AccountData(BaseData):
    """
    Account data contains information about balance, frozen and
    available.
    """

    accountid: str

    balance: float = 0
    frozen: float = 0

    def __post_init__(self) -> None:
        """"""
        self.available: float = self.balance - self.frozen
        self.vt_accountid: str = f"{self.gateway_name}.{self.accountid}"
```

- **`available` 是 `__post_init__` 里算出的派生字段**，不是构造参数。设计铁律：**能推导出来的值不该让外部传入**——否则可能传入与 `balance−frozen` 矛盾的值。自动计算保证一致性、减少调用负担。
- 金融含义：`balance`（总权益）、`frozen`（冻结）、`available`（可动用）。

### 4.7 ContractData（唯一的静态对象，信息最丰富）

```232:262:vnpy/trader/object.py
@dataclass
class ContractData(BaseData):
    """
    Contract data contains basic information about each contract traded.
    """

    exchange: Exchange
    name: str
    product: Product
    size: float
    pricetick: float

    min_volume: float = 1                   # minimum order volume
    max_volume: float | None = None         # maximum order volume

    net_position: bool = False              # whether gateway uses net position volume
    history_data: bool = False              # whether gateway provides bar history data
```

4 个必填核心规格（无默认值）：`name/product/size/pricetick`。

- **`size`（合约乘数）**：期货 1 手 = size 份标的；盈亏 = 价差 × 手数 × size。算钱命门。股票通常 1。

- **`stop_supported`**：是否原生支持停止单。
- **`min_volume`/`max_volume`**：单笔下单量限制。
- **`option_*`**：期权专用（行权价/认沽认购/标的/到期日等），非期权为 None。

### 4.8 QuoteData / LogData（了解）

- **`QuoteData`**（`object.py:264-303`）：做市商**双边报价**（同时挂 `bid_price` 和 `ask_price`），结构类似 OrderData（有 `status`/`is_active()`）。做市/期权策略才深入用。

## 五、请求对象家族

请求对象都**不继承 BaseData**（无 `gateway_name`），方向是「你 → Gateway」。

**「请求」缺少而「委托 OrderData」独有的三个字段**——它们都是"进入市场后才产生的属性"：

| 字段 | 含义 | 为什么请求没有 |
|---|---|---|
| `orderid` | 委托身份证号 | 券商收到后才分配 |

| `traded` | 已成交量 | 还没成交 |

`create_order_data()` 是「意图 → 事实」的转换点：请求经 Gateway 分配 orderid、设 status=SUBMITTING 后，才变成正式委托。请求对象与数据对象对称设计：`OrderRequest.create_order_data()` ↔ `QuoteRequest.create_quote_data()`。

### 5.2 其余请求

- **`SubscribeRequest`**（`object.py:306-317`）：`symbol`+`exchange`，订阅 tick。
- **`CancelRequest`**（`object.py:358-370`）：`orderid`+`symbol`+`exchange`，撤单。通常用 `order.create_cancel_request()` 生成。
- **`HistoryRequest`**（`object.py:373-387`）：带 `start`/`end`/`interval`，查历史 K 线。
- **`QuoteRequest`**（`object.py:390-427`）：做市双边报价，有 `create_quote_data()`。

## 六、constant.py 枚举系统

枚举价值：把"魔法字符串"变成有限、类型安全、IDE 可补全的常量。

### 6.1 交易语义三件套

```10:39:vnpy/trader/constant.py
class Direction(Enum):
    """
    Direction of order/trade/position.
    """
    LONG = _("多")
    SHORT = _("空")
    NET = _("净")


class Offset(Enum):
    """
    Offset of order/trade.
    """
    NONE = ""
    OPEN = _("开")
    CLOSE = _("平")
    CLOSETODAY = _("平今")
    CLOSEYESTERDAY = _("平昨")


class Status(Enum):
    """
    Order status.
    """
    SUBMITTING = _("提交中")
    NOTTRADED = _("未成交")
    PARTTRADED = _("部分成交")
    ALLTRADED = _("全部成交")
    CANCELLED = _("已撤销")
    REJECTED = _("拒单")
```

- **`Direction`**：`LONG/SHORT/NET`。`NET` 用于净持仓模式（只维护净值，正=净多，负=净空）。
- **`Offset`**：`NONE`（股票）/`OPEN`/`CLOSE`/`CLOSETODAY`/`CLOSEYESTERDAY`（后两个上期所/能源所专用）。
- **`Status`**：委托状态机六态。

### 6.2 Direction × Offset 四象限（下单函数对照）

| | `Offset.OPEN`（开仓） | `Offset.CLOSE`（平仓） |
|---|---|---|
| `Direction.LONG`（买入） | 买入开仓 = 做多 → **`buy`** | 买入平仓 = 平空头 → **`cover`** |
| `Direction.SHORT`（卖出） | 卖出开仓 = 做空 → **`short`** | 卖出平仓 = 平多头 → **`sell`** |

**易错点**：`buy`(多开) 和 `cover`(空平) 都是**买入动作**（Direction.LONG），区别只在 offset；`short`(空开) 和 `sell`(多平) 都是**卖出动作**（Direction.SHORT）。即"买入"既可能开多仓也可能平空仓——由 offset 决定。这就是 Direction 和 Offset 是**两个正交维度**的含义。

```152:160:vnpy/trader/constant.py
    TICK = "tick"
```

- **`Exchange`**（`constant.py:82-139`）：拼 `vt_symbol` 用 `.value`（英文码）。分中国/海外/特殊（`LOCAL` 本地生成数据、`GLOBAL` 未支持交易所）。
- **`Interval`**：K 线周期，`value` 是 `"1m"/"1h"/"d"/"w"/"tick"`，在回测/数据库里作 key。
- **`_()` 国际化**：中文字面量是翻译函数包裹的。拼 ID 用的是 `enum.value`；注意 `vt_positionid` 用 `direction.value`（`"多"`/`"空"`），所以持仓 ID 里会出现中文，如 `GW.600000.SSE.多`。

## 七、对象关系图

一次"买入开仓"的完整对象演变：

```
        【意图】                          【事实】
   OrderRequest ──create_order_data()──► OrderData
   (无 status/orderid)                    (status: SUBMITTING
                                                  → NOTTRADED
                                                  → PARTTRADED  ─┐
                                                  → ALLTRADED)   │每笔成交
                                                                 ▼
                                                            TradeData(tradeid_1)
                                                            TradeData(tradeid_2)
                                                            （共享同一 vt_orderid）
                                                                 │累加
                                                                 ▼
                                                            PositionData
                                                            (volume↑, price=均价)
                                                            AccountData
                                                            (frozen/available 变化)

   全程静态参照：ContractData（size, pricetick, net_position）
   枚举贯穿其中：Direction / Offset / Status / OrderType
```

关系总结：
- 一个 `OrderRequest` → 一个 `OrderData`（1:1，经 Gateway 转换）
- 一个 `OrderData` → 多个 `TradeData`（1:N，分批成交）
- 多个 `TradeData` → 累积成 `PositionData`（N:1 汇总）
- `ContractData` 是所有交易的静态背景板（不参与流转，处处被引用）

## 十、常见坑

- **把 `symbol` 当 `vt_symbol`**：所有引擎查询用带交易所后缀的 `vt_symbol`。
- **忽略 `size`（合约乘数）**：期货盈亏 = 价差 × 手数 × size，漏乘会离谱。
- **混淆 `volume`（累计）和单笔量**：算成交量指标用增量。
- **以为 `OrderRequest` 就是委托**：它只是意图，`create_order_data()` 后才是有身份的 `OrderData`。
- **忘了 `PositionData` 按方向分**：期货同一合约多空是两个独立持仓对象。

---

> 核心三点：① `BaseData` + `__post_init__` 复合 ID（前缀 = 命名空间防撞号）；② 数据对象（事实）vs 请求对象（意图）两大家族；③ 枚举定义交易语义。
> 相关源码：`vnpy/trader/object.py`、`vnpy/trader/constant.py`。
